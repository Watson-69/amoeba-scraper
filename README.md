## 🌟 Project Overview

<div align="center">
  <img src="https://capsule-render.vercel.app/api?type=waving&color=gradient&customColorList=6,11,20&height=100&section=header&text=amoeba-scraper&fontSize=40&fontAlignY=35&animation=fadeIn&fontAlign=50" alt="Header" />
</div>

**amoeba-scraper** is a 🚀 **production-ready REST API** that programmatically extracts game metadata from **[FitGirl Repacks](https://fitgirl-repacks.site)** — one of the most trusted sources for compressed game repacks. The API scrapes, normalizes, and stores game information into a MySQL database, exposing it through clean, well-documented endpoints.

> 💡 **Whether you're building a game launcher, a personal collection tracker, or a research tool analyzing repack trends** — this API gives you structured, queryable access to data that would otherwise require manual browsing and parsing.

### ✨ Key Capabilities

<div align="center">

| 🎯 Capability | 📝 Description | Status |
|---------------|----------------|--------|
| **Automated Scraping** | Scheduled or on-demand with pagination, search queries, detail enrichment | ✅ Active |
| **Rich Metadata** | Titles, sizes, magnet links, info hashes, genres, years, posters, descriptions | ✅ Active |
| **Flexible Search** | Full-text search, category filtering, seeder thresholds, multi-sort orders | ✅ Active |
| **Baseline & Regression** | Save baselines, detect staleness, track regressions across runs | ✅ Active |
| **Cron-Ready Sync** | Secure background sync for Vercel Cron, GitHub Actions, schedulers | ✅ Active |
| **Multiple Formats** | JSON, SARIF, CodeClimate, Markdown, GitHub Annotations | ✅ Active |
| **Rate-Limit Friendly** | Configurable delays, exponential backoff, challenge detection | ✅ Active |
| **Idempotent Operations** | Re-running scrapes upserts data; zero duplicates guaranteed | ✅ Active |

</div>

## 💡 Motivation — Why I Built This

<div align="center">
  <img src="https://media.giphy.com/media/v1.Y2lkPTc5MGI3NjExcG55cG55cG55cG55cG55cG55cG55cG55cG55cG55cG55cG55cG55cG55cG55c.gif" width="300" alt="Coding animation" />
</div>

This project began as a **passion project driven by curiosity** 🔥 — not just a utility, but an experiment in building a robust, type-safe data pipeline with modern tooling.

I wanted to explore several things simultaneously:

- 🏗️ **Type-safe full-stack development** with Next.js App Router and strict TypeScript
- 🕷️ **Syntactic web scraping** without headless browsers — using Cheerio for fast, lightweight HTML parsing
- 🗄️ **Database-first architecture** with MySQL, transactions, and upsert patterns for idempotent scrapes
- 📊 **Observability by default** — structured logging, scrape run history, baseline tracking, regression detection
- 🛠️ **Developer experience** — zero-config CLI scripts, environment-based config, comprehensive error handling

The result is a project that's **small enough to understand completely** but **structured like a production service** — with clear separation between scraping, storage, search, and API layers. It's the kind of codebase I'd want to inherit: *boring in the right ways, surprising in none.* ✨

```bash
# 2️⃣ Install dependencies
npm install

# 4️⃣ Initialize the database schema

# 5️⃣ (Optional) Populate with initial data

# 6️⃣ Start development server
npm run dev
```

### 🎮 Games Listing

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/games` | Paginated list of stored games |

**Query Parameters:** `page`, `limit` (max 100), `category`, `sortBy` (`date` \| `size` \| `seeders` \| `name`), `q` (search)

```bash
# 🆕 Newest first, 24 per page
curl "http://localhost:3000/api/games?page=1&limit=24&sortBy=date"

# 🏷️ Filter by category
curl "http://localhost:3000/api/games?category=games"

# 🔍 Search stored data
curl "http://localhost:3000/api/games?q=hades"
```

---

### 🔍 Search with Live Scrape

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/search` | Search with optional live scrape |

**Query Parameters:** `q`, `category`, `source`, `minSeeders`, `page`, `limit`, `sortBy` (`relevance` \| `date` \| `size` \| `seeders`), `live` (`1` to scrape fresh first)

```bash
# 🔍 Basic search
curl "http://localhost:3000/api/search?q=stardew"

# 🎯 With filters
curl "http://localhost:3000/api/search?q=portal&category=games&minSeeders=10&sortBy=seeders"

# ⚡ Live scrape + search
curl "http://localhost:3000/api/search?q=elden+ring&live=1"
```

---

### 📦 Torrent Details

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/torrents/[id]` | Get single torrent by ID |
| `GET` | `/api/torrents/stats` | Get seeder/leecher stats for multiple IDs |

```bash
# 📄 Single torrent
curl "http://localhost:3000/api/torrents/amoeba:base64encodedid"

# 📊 Bulk stats
curl "http://localhost:3000/api/torrents/stats?ids=amoeba:id1,amoeba:id2"
```

### ⏰ Background Sync (Cron)

Designed for automated updates via **Vercel Cron**, **GitHub Actions**, or any scheduler.

```bash
curl -H "Authorization: Bearer your-cron-secret" \
  http://localhost:3000/api/cron/sync
```

> 🔐 Requires `CRON_SECRET` in `.env.local`. Checks first 2 pages for new releases.

## 🗄 Database Schema

<div align="center">
  <img src="https://img.shields.io/badge/MySQL-Schema-4479A1?style=for-the-badge&logo=mysql&logoColor=white" />
</div>

Two tables, created by `npm run db:init`:

```sql
-- 🎮 Scraped game torrent metadata
CREATE TABLE torrents (
  id              VARCHAR(64) PRIMARY KEY,
  title           VARCHAR(500) NOT NULL,
  size_bytes      BIGINT UNSIGNED NULL,
  seeders         INT UNSIGNED DEFAULT 0,
  leechers        INT UNSIGNED DEFAULT 0,
  uploaded_at     DATETIME NULL,
  category        VARCHAR(64) NULL,
  source_site     VARCHAR(128) NOT NULL,
  source_url      TEXT NULL,
  magnet_link     TEXT NULL,
  info_hash       CHAR(40) NULL,
  description     MEDIUMTEXT NULL,
  poster_url      TEXT NULL,
  genres_json     JSON NULL,
  year            SMALLINT UNSIGNED NULL,
  rating          DECIMAL(3,1) NULL,
  details         TEXT NULL,
  last_scraped_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  -- Indexes: fulltext(title, description), category, uploaded_at, seeders, source_site, info_hash, year
);

-- 📊 Scrape run history for monitoring
CREATE TABLE scrape_logs (
  id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  source_site     VARCHAR(128) NOT NULL,
  status          ENUM('success','partial','failed') NOT NULL,
  items_found     INT UNSIGNED DEFAULT 0,
  items_inserted  INT UNSIGNED DEFAULT 0,
  items_updated   INT UNSIGNED DEFAULT 0,
  error_message   TEXT NULL,
  started_at      DATETIME NOT NULL,
  completed_at    DATETIME NULL
);
```

## 🛠 Troubleshooting

<div align="center">
  <img src="https://capsule-render.vercel.app/api?type=waving&color=gradient&customColorList=6,11,20&height=80&section=footer&animation=fadeIn" alt="Troubleshooting" />
</div>

<details>
<summary><strong>🔴 "ECONNREFUSED" / Database connection failed</strong></summary>

- ✅ Verify MySQL is running: `systemctl status mysql` or `mysqladmin ping`
- ✅ Check credentials in `.env.local` match your MySQL user/password
- ✅ Ensure the database exists (run `npm run db:init`)

</details>

<details>
<summary><strong>🟡 "Site blocked or challenged" / Scrape returns 0 results</strong></summary>

- ⚠️ The target site may be rate-limiting or blocking the request
- 🔧 Increase `SCRAPER_DELAY_MS` in `.env.local` (e.g., `2000`)
- 🛡️ Check if challenge page is returned (scraper detects this)
- 🌐 Try again later or use a VPN/proxy

</details>

<details>
<summary><strong>🔵 "Cannot find module" / TypeScript errors</strong></summary>

- 📦 Run `npm install` to ensure all dependencies are installed
- 🔍 Run `npm run build` to check for TypeScript errors
- ✅ Ensure Node.js version is ≥ 20 (`node --version`)

</details>
